1 · The chain

A long chain of people and machines, folded into one model

The kind of breach this project studies starts far from any wallet: a recruiter, a take-home assignment, a poisoned repository. It ends at a signing system that approves what it is handed.

LureA recruiter who does not exist offers a job.
PoisonThe coding assignment carries instructions of its own.
FootholdSomeone runs it. Access spreads quietly.
SignatureA signing system approves a request it should have doubted.
An autonomous wallet agent does all four in one context window.It reads the poisoned text and it proposes the transaction. Nobody stands in between.

Intentlock defends this agent-shaped version of the chain. It would not have stopped malware on a person's laptop or a compromised signing service.

4 · The lock

Two checks on intent, one inside the agent and one in front of the signer

Hardening

The agent is fine-tuned on safe trajectories built from the training scenarios: finish the user's task, treat tool output as data, and say what was ignored. Training uses SafeTune's SafeGrad, which keeps a narrow fine-tune from eroding the model's general refusal behaviour. Plain fine-tuning on the same data is the comparison.

Guard

A second small adapter sees only three things: what the user asked, what the tools just returned, and the exact payload about to be signed. It answers ALLOW or BLOCK with a reason. It never sees the agent's reasoning, so a compromised agent cannot talk it round. Anything it cannot parse is a BLOCK.

6 · Limits

What this does not show

  • The scenarios are synthetic and templated, in English, with mock tools. Results describe this test, not a motivated human attacker.
  • Nobody optimised attacks against the hardened agent or the guard. An adaptive attacker would do better than these templates.
  • One small model. Tiny Aya has 3.35 billion parameters; larger agents may behave differently.
  • The guard is the same model family as the agent and may share its blind spots.
